# ProfitGuard TW — 台灣電商批次損益稽核器

**商品定位**：面向有數十至數百件 SKU 的台灣電商賣家，離線批次試算每個商品的成交費、金流費、活動費、淨利、最低標價與風險標籤。不是免費單件計算器的翻版。

## 使用方式
1. 使用 HTTP 靜態伺服器開啟 index.html（部署到 GitHub Pages 後直接在瀏覽器使用）。
2. 下載 examples/sample.csv，將每列改成獨立單 SKU 假設訂單。
3. 依自己的賣家合約輸入各項費率。0.025 = 2.5%。活動模式：none、rate、threshold_fixed。
4. 匯入 CSV；檢視批次淨利、虧損與最低價格，匯出報告。資料只在瀏覽器本機計算，不上傳。
5. 測試：node --test tests/*.test.js；語法檢查 npm run check。

## 產品與市場假說（尚未驗證付費轉換）
免費單筆費用計算器已存在，差異化是批次 2000 SKU、按商品覆寫費率、活動費突變邊界、目標淨利反推最低價、整批報告下載。目標買家是常使用活動折扣、需要事前核算的中小型賣家。必須以實際流量與付費訂單驗證需求，不能把瀏覽量當銷售。

## 計算口徑
單列模擬獨立 SKU 訂單；費率數值不是官方通用預設。
- 商品淨額 = 標價 × 數量 − 賣家負擔折扣。
- 收入 = 商品淨額 + 買家運費 + 真正撥付賣家的平台補貼。
- 成交費 = round(min(35000, 每件商品淨額) × 數量 × 成交費率)。
- 金流費 = round(收入 × 金流費率)。
- 活動費：none=0；rate=round(商品淨額 × 比例)；threshold_fixed=未滿指定訂單門檻採比例，達門檻採固定費。
- 淨利 = 收入 − 進貨成本 − 物流與包材 − 廣告與其他成本 − 成交費 − 金流費 − 活動費。
- 最低標價：尋找滿足指定目標淨利的最低整數價，將固定活動費的門檻前後切成獨立搜尋區間，以避免非單調跨界錯誤。

**已知限制**：不支援多 SKU 混單分攤、特殊分期付款、特定活動稅務、退貨率模型；匯入 CSV 不能代表賣場正式結算單。費率與抵扣基數以實際合約／賣家中心為準；避免將試算冒充平台官方收費。金流費基數應只計入買家支付與平台確實補貼予賣家的金額。

## 營業驗收
- 工程閘門：fixtures + unit tests + 真實瀏覽器試算與 CSV 匯出，均須有回執。
- 發布閘門：公開可用網址 + 經瀏覽器實測。
- 商業閘門：有效交易入口、真实付費/交付回執、成本紀錄；此階段不得用虛構訂單。
